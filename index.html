What I work on

Ingestion that holds up

Third-party lab and device results into a FHIR-shaped store with an auditable trail. Idempotent writes, so a retry is not a duplicate; typed rejections, so a refused record says why rather than vanishing into a log.

Regulated-shape pipelines

HIPAA and GDPR constraints treated as design inputs rather than a review at the end: retention expressed as policy instead of a cron job, least data held, and identifying fields kept out of the places that do not need them.

App-layer trust

Signing, key handling and validation that does not assume the network is friendly or the client is honest, on services and on devices that are only as trustworthy as their firmware.

Around those: API design and service boundaries, search and indexing on OpenSearch/Elasticsearch, AWS, and the performance work that turns up once a system has real data in it.

Live · the console is the point

Below is a game. The game is the bait; the panel beside it is the work. The browser holds no rules at all. Every click is a command sent to a server, decided there, and answered with either a new state or a typed reason for refusal. Every command after the handshake is signed and carries a counter the server will not accept twice. Every number on that panel is measured; none of it is decoration.

It demonstrates real-time state synchronisation, server-side validation, session resumption and replay protection. It does not demonstrate FHIR or PHI handling: it is the same authoritative-state pattern I ship in production APIs, minus the part where it touches anyone's data.

The game connection starts only when you press Start. Press it and this page opens a connection to the game server, which sees your address the way any server you connect to does. It keeps a match id in your browser so you can pick a game back up. No cookies, no analytics, nothing else about you is kept. Scores are ephemeral and reset weekly.

Every command after the handshake is signed with a key the server mints for this connection and hands to this page, and carries a counter the server will not accept twice. You can read that key in devtools, so the envelope protects the session, not against the player. Anti-cheat is the server refusing illegal moves, and nothing else.

The state digest is how you check no tab is showing you a stale board: open the same match in a second tab and both print the same digest. It is not a security control: the server computes it and the client prints it.
